# 12-Release: Communicate quality and complete the capstone

Level: Intermediate | Time: 2 sessions

## Learn the habit

A release summary makes evidence, gaps, and decisions visible. It does not promise defect-free software or replace the accountable release decision.

Use [Release-Summary.md](../Templates/Release-Summary.md). Include target/build, scope, results, linked defects, blocked/not-run work, residual risks, recommendation, and decision owner.

If 10 cases were planned, 8 passed, 1 failed, and 1 is blocked, report all four numbers. "8/9 executed passed" does not communicate the blocked risk on its own.

## Capstone

1. Review the worked API contract and ask five new questions.
2. Add five meaningful risks to a working copy of the workbook.
3. Design cases using boundaries and state transitions.
4. Execute one exploratory charter and the API lab.
5. Investigate one discrepancy. If none appears, document a requirement gap or use the explicitly fictional training defect.
6. Compare fix options and write retest/regression checks.
7. Produce a release summary for local learning use.
8. Explain what new evidence would be required for a public shared deployment.
9. Add one lesson learned to prevent a future problem.

## Review rubric

Score each 0-2: requirement clarity, risk rationale, test design, reproducibility, evidence quality, solution reasoning, coverage/gaps, release communication. Aim for 12/16 with no zero for evidence or reproducibility.

## Done when

Another learner can follow your evidence, challenge your assumptions, and understand why you recommend release, conditions, or further investigation.

Read [SOLUTION.md](SOLUTION.md) after your attempt.
