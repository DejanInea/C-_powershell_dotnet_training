# Test strategy: project / change

## Goal and target
User goal, target system, build/commit, release scope.

## Test basis and questions
Requirements/contracts, assumptions, unresolved questions and owners.

## Risks and priorities
Link risk register; justify the highest risks and any overrides.

## Approach
Reviews, test levels, boundary/state cases, exploration, automation.
Explain the oracle for important behaviors.

## Environment and data
Configuration, dependencies, isolated data, observability, backup/reset.
Who owns the environment and how do we recognize a setup failure?

## Scope and gaps
Included, excluded, not yet testable, future requirements.

## Execution and evidence
Commands/tools, run ID, evidence location, status definitions, issue links.

## Entry / exit criteria
What makes testing feasible? What evidence or open risk affects release?
Name the accountable decision owner; distinguish recommendation from approval.

## Schedule and learning
Order the investigations by value. State when the plan will be reviewed.
