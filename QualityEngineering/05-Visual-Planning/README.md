# 05-Visual-Planning: Connect risks, tests, and project stages

Level: Beginner | Time: 45-60 minutes

## Learn the habit

Plan what you need to learn, not merely which tool to open. A traceability row connects a requirement to risks, checks, defects, and evidence. It makes gaps visible.

Open the workbook's Coverage and Lifecycle sheets. A test-case ID shows a planned relationship, not proof of execution. A defect link shows an investigation, not proof that all related behavior is broken.

## A practical plan

1. Review requirements and questions.
2. Rank risks.
3. Choose test levels and data/environment needs.
4. Select a small smoke set.
5. Execute targeted checks and exploration.
6. Review defects and gaps.
7. Summarize residual risk for the release decision.

Use [Test-Strategy.md](../Templates/Test-Strategy.md). Name who makes the release decision and what evidence would block or condition it.

## Exercise

Map three requirements to at least one positive and negative check where appropriate. Identify a high risk with no automated coverage. Place its investigation in the lifecycle plan with an owner.

Draw a board: Proposed -> Ready -> Running -> Investigating -> Retesting -> Done. Explain how work status differs from test outcome.

## Done when

You can answer "What remains untested?" without opening every test case. You do not interpret green cards as complete quality evidence.
